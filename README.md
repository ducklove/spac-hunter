# spac-hunter

국내 상장 스팩을 `현재가 / 공모가` 중심으로 정렬하고, 합병·청산 일정을 함께 보는 정적 대시보드입니다.

## 실행

```powershell
python fetch_data.py --history-pages 3
```

생성되는 파일:

- `data.json`: 대시보드가 `fetch()`로 비동기 로드하는 전체 데이터
- `data.js`: 같은 페이로드의 `window.SPAC_DATA = …;` 래핑본 — `file://` 등 fetch가 막힌 환경용 폴백
- `current.json`: 현재가 중심의 가벼운 스냅샷

그 다음 `index.html`을 브라우저에서 열면 됩니다.

종료 코드는 `0` 정상, `1` 수집 실패, `2` 안전 가드 거부입니다. 직전 데이터 대비 종목 수가 급감하거나 시세 수집률이 50% 미만이면 기존 데이터를 보호하기 위해 쓰기를 거부하고 exit 2로 종료하며, 의도한 축소라면 `--force`로 우회할 수 있습니다. 샘플 데이터 폴백은 `--sample`을 명시했을 때만 동작하고(라이브 수집 실패 시 데이터를 쓰지 않고 exit 1), 샘플 데이터는 가드에 걸릴 수 있어 `--sample --force`를 권장합니다.

생성된 `data.js`/`data.json`의 구조와 두 파일의 페이로드 일치 여부는 다음으로 검증합니다(표준 라이브러리만 사용, 실패 시 exit 1).

```powershell
python validate_data.py
```

`--path`/`--json-path`로 검증 대상 파일을, `--min-count`로 최소 종목 수 기준을 바꿀 수 있습니다(`--json-path ""`는 data.json 검증 생략).


## 개발

```powershell
pip install -r requirements.txt -r requirements-dev.txt
ruff check spac_hunter tests fetch_data.py validate_data.py
pytest -q
node --test tests/js
```

로컬 프리뷰는 `python -m http.server`를 띄워 접속하거나, `index.html`을 브라우저에서 직접 열면 됩니다(별도 빌드 없음). 대시보드는 `data.json`을 `fetch()`로 비동기 로드하며, fetch가 막히는 `file://` 환경에서는 자동으로 `data.js` `<script>` 폴백을 사용합니다.

## 화면 시세 자동 갱신

`common_preferred_spread`와 동일한 공용 프록시(`https://ducklove.duckdns.org:3298`)로 초기 데이터 로드 직후, 이후 5분마다 최신 시세를 조회합니다. 숨겨진 탭은 조회를 쉬고 탭 복귀 시 즉시 조회하며, **시세 새로고침** 버튼도 같은 경로를 사용합니다. 초단위 체결 스트리밍이 아니라 5분 주기 조회 방식입니다.

`assets/live-prices.js`가 숫자 코드를 20개씩 일괄 조회하고, 영문 포함 코드 및 일괄 조회 누락은 최대 4개 동시 개별 조회로 보완합니다. 요청별 8초·전체 25초 제한과 중복 실행 방지, HTTP 429 시 추가 요청 중단을 적용합니다. 프록시 조회 시각이 60초 이상 오래되거나 가격이 잘못된 응답은 적용하지 않으며, 실패한 종목은 마지막 가격을 보존하고 갱신 건수를 표시합니다.

현재가·등락·거래량·거래대금·시가총액과 공모가 대비 비율, 기대수익률, 배지, 정렬 및 상단 요약을 함께 갱신합니다. 시세 확인 시각은 체결 시각과 다르며 종목 상세에서도 확인할 수 있습니다. 공시·일별 이력과 합병 이벤트의 일별 종가 통계는 기존 일일 수집으로 갱신하고 별도 기준 시각을 유지합니다. 화면 조회는 저장 파일이나 알림 기록을 변경하지 않습니다.

## 방문 이후 새 이벤트

화면 상단 **새 이벤트** 영역에서 신규 상장, 합병 신청·확정·철회, 해산사유 발생, 유니버스 제외(상폐 추정)를 확인합니다. 종목 카드·표·상세·해당 일정에도 `NEW` 배지가 붙으며, **종목 보기**로 상세 화면에 이동하거나 **원문**으로 공시를 열 수 있습니다. 개별 **확인** 또는 **모두 확인**을 누르기 전까지 배지는 새로고침·재방문 후에도 유지됩니다.

`assets/event-news.js`가 `alerts.json`과 종목 이벤트를 날짜·유형·종목코드로 합쳐 중복을 제거합니다. 최초 방문은 한국 날짜 기준 최근 7일을 보여주고, 이후에는 이전에 없던 이벤트와 미확인 이벤트를 보여줍니다. 당일 추가 이벤트 및 뒤늦게 수집된 과거 공시도 식별자 차이로 감지합니다. 미래 청산예정일과 가격 변동 알림은 이 영역에서 제외합니다.

방문 시각·이벤트 식별자·미확인 상태는 현재 브라우저의 `localStorage`(`spac-hunter-event-news-v1`)에 저장됩니다. 다른 기기나 저장소 삭제 후에는 첫 방문으로 처리됩니다. 알림 조회는 첫 로드 및 시세 갱신 완료 시 실행하며, 알림 조회 실패 시 기존 방문 기준을 보존하고 저장 데이터로 표시합니다. 공시 이벤트의 원천 갱신 주기는 기존 일일 수집과 같습니다.

## 데이터 소스

- KRX 상장종목검색: KOSDAQ 종목명에 `스팩` 또는 `SPAC`이 포함된 종목을 universe로 사용
- KIND 상장법인목록: 상장일, 업종, 주요제품 보강
- 합병 공시: OpenDART API(키 설정 시 최우선) → KIND 공시검색 → DART 화면 스크래핑 폴백 체인. `회사합병 결정`/`SPAC 합병(예비심사청구대상)`은 `합병 신청`, `상장예비심사결과 통지(승인)` 등은 `합병 확정` 상태로 분류하고, `해산사유 발생` 공시는 해산 배지·이벤트로 표시
- 네이버 증권: 현재가와 최근 일별 시세
- 합병 공시가 있는 종목은 더 긴 일별 시세를 가져와 공시 직전가, 다음 거래일, 최신가, 이후 고점·저점 수익률을 계산
- 시장 통계: 공모가 미만 종목수 추이, 신규등록 월별 추이, 합병 신청/확정/철회 추이, 표본 기준 합병 성사 확률과 성사 기간, 스폰서(증권사)별 통계
- 상폐 아카이브: 유니버스에서 사라진 스팩(합병 신상장·상폐)을 `archive.json`에 마지막 가격·합병 상태와 함께 기록하고, 합병 성사 통계에 아카이브 표본을 합산해 생존편향을 줄입니다 (아카이브 도입 이전에 상폐된 과거 사례는 미포함)
- 합병 후 주가 추적: 합병 신상장으로 아카이브된 스팩은 존속합병(같은 종목코드)이면 자동으로, 소멸합병(새 종목코드)이면 `overrides.json`의 `postMergerCode` 매핑으로 합병법인의 시세를 계속 수집합니다. 아카이브 시점 이후 일별 시세를 `archive.json`의 `postMerger` 블록에 누적하고, 스팩 최종가·공모가 대비 수익률과 이후 고점·저점을 `statistics.postMergerFlow`로 요약해 대시보드 "합병 후 주가 흐름" 패널에 표시합니다. 자동(동일 코드) 추적은 아카이브 후 1년까지 갱신하며(이후 마지막 데이터 보존), `postMergerCode` 매핑은 기간 제한 없이 추적합니다.

`data.js`에는 schemaVersion 2 형식으로 수집 요약(collection)이 함께 기록되어, 대시보드가 수집 상태와 데이터 신선도를 표시하는 데 사용합니다.

### OpenDART 연동 (선택)

[OpenDART](https://opendart.fss.or.kr/)에서 무료 회원가입 후 인증키를 발급받아 환경변수 `OPENDART_API_KEY`(또는 `DART_API_KEY`)로 설정하면(로컬 실행 시 환경변수, CI는 저장소 Settings → Secrets and variables → Actions에 등록) 공시 수집이 화면 스크래핑 대신 공식 API를 최우선으로 사용해 더 안정적으로 동작합니다. 키가 없으면 자동으로 기존 KIND → DART 체인을 사용하므로 동작 차이가 없습니다. 고유번호 매핑(corpCode.xml)은 `.cache/`에 7일간 캐시됩니다.

키가 설정되면 다음 두 기능이 추가로 활성화됩니다.

- **증권신고서 자동 추출**: 종목별 투자설명서/증권신고서 원문에서 확정공모가·공모주식수·예치금·예치이율·예치기관·청약/납입일을 추출해 `filings.json`에 축적합니다. 추출값은 `overrides.json` 다음 순위의 폴백으로 사용됩니다(공모가: overrides > 신고서 > 기본 2,000 / 예치이율: overrides > 신고서 이율 > KOFR). 실행당 문서 요청 수는 `--filing-doc-limit`(기본 40)로 제한되어 매일 조금씩 채워지며, 특정 종목을 다시 추출하려면 `filings.json`에서 해당 엔트리를 삭제하면 됩니다. 추출은 best-effort라 값 범위 검증을 통과한 필드만 사용됩니다.
- **청약 캘린더**: 최근 30일 발행공시에서 상장 전 스팩의 증권신고서를 찾아 `data.js`의 `ipoCalendar`로 제공하고, 대시보드 "다가오는 일정"에 공모 청약 컬럼으로 표시합니다.

## 알림

라이브 갱신(`--sample` 아님)이 성공하면 직전 `data.js`와 비교해 다음 이벤트를 감지합니다.

- 합병 신청 / 확정 / 철회 공시 발생, 해산사유 발생
- 공모가 이하 진입 / 회복 (현재가/공모가 1.00x 교차)
- 청산 6개월 이내 진입, 신규 상장
- 유니버스 제외(상폐 추정) — 아카이브 등록과 동시에 알림

감지된 알림은 `alerts.json`(최신순 누적, 최대 500건)과 `alerts.xml`(RSS 2.0, 최신 50건)로 기록되어 GitHub Pages에서 RSS 리더로 구독할 수 있습니다. 저장소 secrets에 `TELEGRAM_BOT_TOKEN`과 `TELEGRAM_CHAT_ID`를 등록하면 새 알림 요약이 Telegram으로도 발송됩니다(미설정 시 건너뜀, 발송 실패는 파이프라인을 중단시키지 않음).

## 주요 계산

```text
현재가 / 공모가 = 현재가 / 공모가
공모가 괴리 = 현재가 / 공모가 - 1
예상 상장폐지일 = 상장폐지 사유일 + 13일
  상장폐지 사유일 = 합병 미신청: 납입일 + 31개월(30개월 관리종목 + 1개월), 30개월 이후 합병 철회: 철회일 + 1개월
                    합병 진행 중: 납입일 + 36개월(합병등기 기한), 해산사유 발생 공시가 있으면 그 날짜가 상장폐지일
청산금 수령 예정일 = 예상 상장폐지일 + 102일(잔여재산 분배 소요일)
추정 청산분배금 = 기준 예치금(1주당) × Π(1 + 순이율 × 예치일수/365)   ← 예치 계약(재예치)마다 곱함
  기준 예치금 = 최근 신탁계약내용변경 공시의 '변경 후 예치금액' / 공모주식수 (없으면 공모가)
  순이율     = (공시 예치이율 - 신탁보수) × (1 - 이자 원천징수 15.4%)
  신탁보수   = 이 스팩의 재예치 공시 예치금으로 역산 > 같은 증권사 스팩 역산값 > 기본 0.1%p
  재예치     = 공시된 이율 변경일, 그 사이·이후는 12개월마다. 수령 예정일까지 마지막 이율 유지
단순 기대수익률 = 추정 청산분배금 / 현재가 - 1
연환산 기대수익률 = (추정 청산분배금 / 현재가)^(365 / 청산금 수령까지 잔여일수) - 1
```

예치금 이자 계산은 실제 공시로 검증했습니다. 신탁계약내용변경 공시의 변경 전/후 예치금액을 보면 공모자금은 계약 기간 동안 단리로 이자가 붙고, 만기(재예치) 때 신탁보수와 법인 이자소득 원천징수(법인세 14% + 지방소득세 1.4%)를 뺀 이자가 원금에 합산됩니다. 교보14호스팩(3,850,000주)의 7,700,000,000 → 7,937,109,180 → 8,163,295,018 → 8,245,338,592원 세 번의 재예치 잔액을 이 방식으로 1주당 0.05원 이내로 재현합니다. 예전 계산처럼 세전 이율을 그대로 복리로 쌓으면 이자를 18-22% 과대 추정합니다(3년이면 1주당 약 35-40원). 신탁보수 유무는 스팩마다 다르므로 공시에서 역산합니다. 재예치 공시마다 `보수 = 변경 전 이율 - (변경 후/변경 전 예치금액 - 1) × 365/일수 ÷ (1 - 0.154)`를 계산해 중앙값을 0.05%p 단위로 맞춥니다(직전 재예치일부터의 계약을 우선, 없으면 첫 계약을 만기에서 정수 개월 거슬러 계산). 2026-09 상장 스팩에서 KB·미래에셋·하나·한국투자 계열은 0%p(정기예금형), 교보·신한·DB·SK·유안타·유진·NH·삼성 등은 0.1%p(특정금전신탁)로 뚜렷하게 갈렸고, 2종목 이상인 증권사 9곳 모두 한 값으로 모였습니다. 그래서 첫 재예치 전인 신규 스팩은 같은 증권사 스팩들의 역산값을 따르고(값이 엇갈리는 증권사는 제외), 근거가 전혀 없을 때만 기본 0.1%p(`--trust-fee-pct`)를 씁니다. 첫 계약만으로 역산한 값은 예치 시작일 며칠 오차로 흔들리므로 같은 증권사 값과 0.05%p 이내면 증권사 값을 씁니다. 종목 상세의 '이자 차감'에 보수 근거가 표시되며, `overrides.json`의 `trustFeePct`가 항상 우선합니다. 주주 단계에서 원천징수되는 의제배당 소득세는 매수가격마다 달라 분배금·수익률 계산에 넣지 않습니다(세전 수익률).

청산금 수령 예정일은 실제 퇴출 경로와 분배 절차를 반영합니다. 합병을 신청하지 않은 스팩은 상장일+36개월이 아니라 코스닥 규정에 따라 납입일+30개월에 관리종목, 1개월 뒤 상장폐지 사유가 발생해 3-5개월 먼저 상장폐지됩니다(한국제13·IBKS제23·하나30·대신밸런스제17·신영10호의 사유 발생일이 납입+31개월과 0-2일 차이). 상장폐지(해산) 뒤에는 채권신고 공고·청산재산 보고 주총·분배기준일을 거치며, 2025-2026년 해산 스팩 9곳의 공시 일정에서 상장폐지일부터 잔여재산 분배일까지 94-114일(중앙값 102일)이 걸렸습니다. 해산 7곳에 적용하면 예상 상장폐지일은 실제와 ±2일, 예상 수령일은 -12일~+6일 차이였습니다(기존 기준인 상장일+36개월은 실제 수령보다 32-49일 늦었습니다). 연환산 기대수익률은 이 수령 예정일까지의 보유일수로 계산하며, 예치금 이자도 그날까지 붙는다고 봅니다. 청산기한(`liquidationDate`, 상장일+36개월)과 이를 쓰는 배지·알림은 그대로입니다. 납입일은 신고서 추출값이 청약기간 안에 있으면(청약개시일을 잘못 읽은 경우) 청약 종료 2영업일 뒤로 봅니다.

3년차 예치 계약은 1년을 채우지 못하는 경우가 많습니다. 청산 스팩 57곳의 재예치 공시 142건을 보면 3년차에 새로 시작한 계약은 대부분 3-6개월 등 12개월 미만이었고, 해산 때 걸려 있던 마지막 계약은 두 부류였습니다. 약 15곳은 상장폐지 1-2개월 전 단기 상품으로 바꿔 분배 시점에 만기를 맞췄고, 약 40곳은 3년차 시작일에 맺은 1년 계약이 분배일보다 3-7주 늦게 만기였습니다. 신탁계약 특약(교보14·NH25·BNK1·신영10호 투자설명서)상 예금 만기 전에 인출하면 예치일부터 전체 기간에 은행 게시 중도해지이율이 적용됩니다. 중도해지이율과 실제 분배액이 공개되지 않아 추정치는 약정 이율 그대로 두고, 현재 예치 계약의 만기가 청산금 수령 예정일보다 늦으면 종목 상세에 경고합니다(공시 만기일·계약기간이면 '위험', 미공시로 직전 계약 기간 또는 12개월을 가정하면 '가능성'). 만기는 재예치 공시의 "계약 만기일", "2025년 9월 30일 만기 상품", "3개월 만기" 같은 문구에서 읽습니다. 유진·신한 일부의 '계약만기일'은 공모 때 맺은 3년 신탁계약의 만기입니다.

신영10·하이7호 등 일부 스팩은 공시 예치금액을 세금·신탁보수 차감 전(세전)으로 적고 차감은 다음 재예치 때 합니다(공시 주석 "제비용 차감 전 금액"이 문자 그대로인 경우). 순이율/약정이율이 0.93-1.07인 공시가 있으면 세전 표기로 판정해 공시 잔액 기준점과 보수 역산을 쓰지 않고 이율 구간으로 계산합니다(신영10호: 공시 잔액 그대로 쓰면 1주당 5.5원 과대).

공모가는 `overrides.json` > 증권신고서 추출값(OpenDART 키 설정 시) > 기본 2,000 순서로 결정됩니다. 최초 예치이율은 첫 재예치 공시의 '변경 전' 이율이 있으면 신고서 본문 추출값보다 우선합니다(신고서 추출 3.0% vs 실제 3.75% 같은 오차 보정). 청산일은 `overrides.json`에 값이 없으면 KIND 상장일 + 36개월로 추정합니다. 일반 운영비, 상장비, 합병 추진비는 기본 계산에서 공모예치금 차감 항목으로 보지 않습니다. 확정 분배금이 공시되면 `overrides.json`의 `liquidationValuePerShare`·`payoutDate`로 보정합니다. 공시 예치이율이 없으면 개별 기대수익률은 표시하지 않고, KOFR 최신 공시금리는 금리 시나리오 기본값에만 씁니다.

차감 가정은 실행 옵션으로 바꿀 수 있습니다: `--trust-fee-pct`(근거 없을 때의 기본 보수, 기본 0.1), `--interest-tax-pct`(기본 15.4), `--payout-lag-days`(상장폐지→분배, 기본 102).

수동 금리를 쓰려면 다음처럼 실행합니다.

```powershell
python fetch_data.py --trust-rate 0.025 --history-pages 3
```

## overrides.json 운영

`overrides.json`은 공모가, 실제 납입일/청산일, 합병 신청/확정 공시일, 예치금 기반 청산분배금 등을 보정하는 핵심 수동/반자동 레이어로, 공시 기반 기대수익률의 정확도를 높입니다. 이제 저장소에 커밋되어 매일 CI 데이터 갱신에도 동일하게 적용됩니다. 키 형식과 작성 예시는 `overrides.example.json`을 참고하세요.

예치금 계산 보정 키: `trustFeePct`(신탁보수 %p, 공시 역산값보다 우선), `interestTaxPct`(이자 원천징수 %), `payoutDate`(잔여재산 분배일이 공시되면 입력, 연환산 기준일).

소멸합병으로 스팩 코드가 사라지고 합병법인이 새 코드로 재상장된 경우, 해당 스팩 키에 `"postMergerCode": "새종목코드"`를 넣으면 합병 후 주가 추적이 새 코드로 이어집니다(존속합병은 매핑 없이 자동 추적).

## 데이터 안전장치

- 샘플 폴백 차단: `--sample` 없이 라이브 수집이 실패하면 샘플 데이터로 대체하지 않고 exit 1로 종료해 기존 데이터를 보존
- 쓰기 가드: 종목 수 급감 또는 시세 수집률 50% 미만이면 쓰기를 거부(exit 2), `--force`로만 우회
- `validate_data.py`: 생성된 `data.js` 구조를 검증하며, CI에서는 갱신 직후 실행되어 실패 시 커밋·배포를 중단
- 갱신 실패 알림: 스케줄 갱신이 실패하면 `[data-refresh] 자동 데이터 갱신 실패` 이슈를 자동 생성하고, 이미 열려 있으면 실행 링크를 코멘트로 추가

## CI 구성

- `.github/workflows/pages.yml`: 매일 18:10 KST(크론) 또는 수동 실행 시 `python fetch_data.py --history-pages 12 --merger-history-pages 60`로 데이터를 갱신하고, `validate_data.py` 검증을 통과하면 `data.js`/`data.json`/`current.json`을 main에 커밋한 뒤 GitHub Pages로 배포합니다. 스케줄 실행 실패 시 이슈로 알립니다.
- `.github/workflows/quality.yml`: PR과 push(main, `claude/**`)에서 `ruff check`와 `pytest -q`, `node --test tests/js`(프론트엔드 포맷터 테스트)를 실행합니다. `data.js`/`data.json`/`current.json`/`docs/**`만 바뀐 커밋은 건너뜁니다.
